# Знание — сила: Arena

Браузерный multiplayer-квиз в стиле ТВ-шоу. Ведущий показывает 3D-арену на большом экране, игроки подключаются с телефонов по QR-коду, отвечают на вопросы, а их роботы бегут на платформу выбранного ответа. Под неправильными платформами открываются люки.

## Стек

| Часть | Технологии |
|---|---|
| `client/` | React 18, TypeScript, Vite, Three.js, Rapier (`@dimforge/rapier3d-compat`), socket.io-client, qrcode |
| `server/` | Node.js, TypeScript, Express, Socket.IO, selfsigned (HTTPS для локальной сети) |
| `shared/` | Общие типы состояния, события, конфиг, тема, вопросы |

Сервер — единственный источник истины: он хранит комнаты, игроков, ответы, очки и таймеры, управляет машиной состояний `LOBBY → INTRO → [POWERUPS] → QUESTION → LOCKED → RUNNING → REVEAL → DROP → NEXT_QUESTION → … → FINAL` и рассылает состояние всем клиентам. Клиент только отправляет действия (ответ, профиль, фото); правильный ответ уходит клиентам только с фазы `REVEAL`, т.е. после того как роботы добежали до платформ. Ведущий может поставить игру на паузу — таймеры сервера и 3D-сцена замирают. Физика (Rapier) работает только на экране ведущего: сервер задаёт «куда бежать» и «какие люки открыть», падение считается физикой локально. Телефоны 3D не загружают — 3D-чанк грузится лениво только на `/host`.

```
client/src/
  game/        arena/ (сцена, раскладка, текстуры, конфетти) characters/ (робот) platforms/ (люки) physics/ camera/
  screens/     Home, host/HostScreen, player/ (PlayerApp, PhotoStep, PlayView)
  network/     сокет, сессии (токены в localStorage), синхронизация часов
  ui/          звуки (Web Audio), иконка робота
server/src/
  game/Room.ts            машина состояний комнаты, очки, боты
  room/RoomManager.ts     создание/удаление комнат
  websocket/handlers.ts   события Socket.IO
shared/src/    config.ts, theme.ts, questions.ts, types.ts
e2e/run.mjs    сквозной тест в headless Chrome (ведущий + 2 телефона + боты)
```

## Запуск одним кликом (Windows)

В корне проекта лежат файлы, запуск двойным кликом:

- **«Запустить игру.cmd»** — режим для игры с телефонами (HTTPS, камера работает). Всегда новая комната, без ботов.
- **«Тест с ботами.cmd»** — то же самое, но сразу с 6 ботами.
- **«Разрешить доступ с телефонов.cmd»** — запустить **один раз**, если телефон не открывает игру по QR. Попросит права администратора и откроет порты 3001/5173 в брандмауэре Windows (часто Wi-Fi помечен как «Общедоступная сеть», и Windows блокирует входящие подключения).

Если и после этого телефон не подключается — роутер изолирует устройства (гостевая сеть / «изоляция клиентов»). Тогда используйте HTTPS-туннель (см. ниже).

## Знакомство и спецприёмы

**Знакомство.** В анкете игрок пишет «фразу о себе» (поле подсказывает случайный вопрос: «Любимая фраза», «Девиз по жизни»…). Пока игра не началась, на экране ведущего все игроки анонимны («Игрок #1…»). После «Начать игру» идёт карточка с правилами, затем по очереди карточки игроков: фото, имя и фраза (по 5 секунд, кнопка «⏩ Дальше» пропускает). Робот игрока раскрывается в свой черёд.

**Спецприёмы.** За верный ответ с шансом 40% выпадает случайный приём (максимум 3 в запасе; новый заменяет случайный старый, если запас полон). Перед следующим вопросом, если у кого-то есть приёмы, открывается окно на 7 секунд («⚡ Этап спецприёмов», ведущий может его пропустить). Кто применил атаку, не раскрывается; цель видна на арене.

| Приём | Действие | Как выглядит на арене |
|---|---|---|
| ❄️ Заморозка | кнопки ответов у цели во льду: каждую надо разбить тремя тапами | робот синеет, весь в сосульках, дрожит от холода, обнимает себя, пар изо рта |
| ⏳ Урезать время | у цели на 3 секунды меньше на ответ | над роботом тикают часы-будильник |
| 🟢 Слизь | ответы закрыты слизью, её надо стереть пальцем | робот зелёный, хлюпает при ходьбе, пока открыт вопрос — стряхивает слизь с себя, капли летят в стороны |
| 💣 Бомбы | по экрану цели летают бомбы; тап по бомбе — ответ потерян | вокруг робота кружат маленькие бомбы с дымящимся фитилём |
| 🛡️ Щит | отражает следующий приём против вас | щит в руке (виден всем) |
| 💰 Ставка | на игрока: если он ответит верно, вы получаете +50% его очков за вопрос | мешок денег в руке (на кого ставка, не видно) |
| 👋 Пощечина (эмоция) | **шуточная эмоция**, на игру не влияет и щитом не отражается: робот подбегает к другому игроку и даёт ему пощечину | у жертвы кружится голова, над ней летают звёздочки |
| 🚀 Катапульта | **редкий** (около 3% выпадений): цель вылетает из вопроса, не отвечает, очки не меняются (даже при «Ва-банке») | под роботом цели вырастает деревянная катапульта, он запрыгивает в ковш, рычаг натягивается и швыряет его в экран ведущего: робот врезается в него (трещины на «стекле») и медленно сползает вниз |

**Показ приёмов.** Когда окно приёмов закрылось, все роботы встают в ряд, и применённые приёмы разыгрываются по очереди: камера плавно переезжает к паре, нападающий подбегает с предметом в руке (ледяной куб, слизь, часы, бомба, ракета, мешок денег) и бьёт цель им, после чего на цели появляется эффект. Щит, отразивший удар, вспыхивает. Так видно, кто на кого применил приём. Ведущий может пропустить показ кнопкой «⏩ Пропустить».

Посмотреть все эффекты вблизи: откройте `/gallery` на компьютере ведущего (или `node e2e/gallery.mjs`, он сохранит скриншоты, в том числе последовательность катапульты).

Боты применяют приёмы только друг на друга. Для тестов: переменные окружения `QUIZ_POWERUP_CHANCE` (шанс выпадения, 0…1; «Тест с ботами.cmd» ставит 0.9) и `QUIZ_POWERUP_TYPES` (например `freeze,bombs`).

## Раунды, категории, твисты

- **Структура игры.** 3 раунда по 5 вопросов (15 вопросов). Категория меняется раз в раунд: перед первым вопросом раунда крутится карусель тем, остальные вопросы раунда идут в той же теме. В раунде не повторяются темы. Для этого в банке должно быть не меньше 5 вопросов в категории (в стартовом банке 56 вопросов, по 7 в 8 категориях: география, наука, литература, история, спорт, музыка, кино и сериалы, видеоигры; максимум 120).
- **Каждая игра разная.** Темы раундов и вопросы выбираются случайно из банка. Для быстрых тестов: переменные `QUIZ_ROUNDS` и `QUIZ_QUESTIONS_PER_ROUND`.
- **Твист раз в раунд.** Один случайный вопрос раунда (не первый) играется с особым условием, перед ним показывается карточка:
  - ✨ **Двойные очки**: все очки за вопрос ×2;
  - 🎰 **Ва-банк**: верный ответ ×2, ошибка или молчание отнимает 100 очков (ниже нуля счёт не уходит);
  - ⏱️ **Блиц**: 7 секунд на ответ.
  (`QUIZ_MUTATOR=double|allin|blitz|none` фиксирует твист для тестов.)
- **Серии.** Верные ответы подряд: с третьего даётся бонус +20, +40, +60 (максимум +80), над роботом горит 🔥. Ошибка обнуляет серию.
- **Реакции.** На телефоне под вопросом шесть кнопок 🔥😂😱👏❤️🤔: эмодзи вылетает над роботом на большом экране (раз в 0,7 секунды).
- **Финал.** Пьедестал с тремя лучшими (медали, крупные фото, ступени растут от 3-го места к 1-му), справа полный рейтинг.
- **Знакомство.** На карточке игрока крупное фото рядом с роботом, имя и фраза.

## Прочее

- **Код игры** состоит из 4 цифр, на телефоне открывается цифровая клавиатура.
- **Вопрос на экране ведущего скрыт, пока игроки отвечают**: читать его нужно на телефоне. Когда ответы приняты, вопрос и варианты появляются на большом экране и на платформах.
- **Пауза между вопросами** 3 секунды (6 после последнего вопроса раунда).
- **Цвета роботов**: 20 штук, выбранный игроком цвет занят, другие выбрать его не могут.
- **Финал**: 3D-пьедестал, на нём три победителя, остальные по бокам аплодируют, над каждым его место.
- **Телефон сам догоняет состояние** (раз в 4 секунды и при возвращении на вкладку), если пропустил обновление.

## Музыка и звуки

- **Музыка под каждый этап** (кнопка 🔊/🔇 на экране ведущего выключает всё; музыка включается после первого клика ведущего, это требование браузера):

| Этап | Музыка |
|---|---|
| Лобби | файл из первой версии (`client/public/music/bg.mp3`) |
| Знакомство | светлый мажорный бит |
| Карусель категорий | быстрый игровой аркадный бит |
| Твист-вопрос | тревожная, медленная |
| Этап приёмов | «шпионский» стаккато |
| Вопрос | тихий пульс с тиканьем (не мешает думать) |
| Бегут к ответам | напористая барабанная дробь |
| Раскрытие ответа и люки | торжественный мажор |
| Между вопросами | спокойный грув |
| Финал | файл из первой версии (`final.mp3`) |

  Остальные треки синтезируются прямо в браузере (`client/src/ui/music.ts`), поэтому ничего не скачивается и нет вопросов с лицензиями. Чтобы послушать их без игры: `npm run build && npm run music:preview`, WAV-файлы появятся в `e2e/music-preview/`.
- **Звуки.** Тики карусели, барабанная дробь, ахи и радость при раскрытии, удар люков, приземления, твист, серия, звуки реакций и приёмов, фанфары пьедестала, аплодисменты.
- **Анимации роботов.** Задумчивая поза на вопросе, прыжок при ответе, дрожь в последние секунды, наклон и пыль при беге, приземление со сжатием, испуг у ошибившихся и радость у правых, кувырок при падении, всплывающие «+очки», корона лидера, вращение победителя, лёд и слизь под действием приёмов, лёгкая тряска камеры.
- **Фото.** Фильтры, стикеры, искажения «Рыбий глаз», «Вмятина», «Волны», «Растяжение» и рисование поверх фото.

## Вопросы

Кнопка **«📝 Вопросы»** на экране ведущего (или адрес `/questions`) открывает редактор: текст вопроса, 4 варианта, правильный ответ кружком, добавление/удаление/порядок. Вопросы хранятся в `data/questions.json` (путь можно сменить переменной `QUESTIONS_FILE`). Изменения применяются к следующей игре («Новая игра» или «Перезапустить»). Редактор доступен только с компьютера ведущего, не с телефонов.

Что делает запуск:
1. при первом запуске ставит зависимости;
2. собирает игру;
3. запускает сервер;
4. открывает в браузере экран ведущего.

Окно должно оставаться открытым, пока идёт игра; закрыли окно — сервер остановлен. Если игра уже запущена, файл просто откроет браузер. Запуск идёт через `cmd` и Node, поэтому запрет скриптов PowerShell (`npm.ps1 … выполнение сценариев отключено`) ему не мешает.

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

- Экран ведущего: <http://localhost:5173/host> → «Создать игру».
- В QR-коде автоматически подставляется адрес компьютера в Wi-Fi (например `http://192.168.31.254:5173/join/ABCD12`), а не `localhost`.
- Телефоны должны быть в той же Wi-Fi сети.

Проверка без телефонов: <http://localhost:5173/host?testPlayers=6>. После «Создать игру» добавятся 6 ботов (`Player 1…6`), они отвечают случайно. В тестовом режиме в лобби есть кнопка «+ 3 бота».

### Продакшн-режим (один порт)

```bash
npm run build
npm start              # http://localhost:3001/host
```

Порт задаётся `PORT` (по умолчанию 3001).

## Тестирование с нескольких телефонов

`getUserMedia` (живое превью камеры) браузеры разрешают только в secure context: `https://` или `localhost`. Варианты, от простого к удобному:

1. **Обычный HTTP в Wi-Fi** (`npm run dev` или `npm start`). Всё работает, кроме живого превью камеры. На шаге фото будет кнопка «📷 Снять через камеру телефона»: откроется системная камера, снимок попадёт в редактор (фильтры, зеркало, стикеры работают).
2. **HTTPS в локальной сети** с самоподписанным сертификатом:
   ```bash
   npm run build
   npm run start:https        # https://<IP>:3001/host
   ```
   или в dev-режиме: `npm run dev:https` (`https://<IP>:5173/host`). На каждом телефоне один раз подтвердите предупреждение о сертификате («Подробнее → Перейти на сайт»). Сначала откройте адрес на экране ведущего и примите сертификат там.
3. **HTTPS-туннель** (настоящий сертификат, работает и через мобильный интернет):
   ```bash
   npm run build
   npm start                                   # терминал 1
   cloudflared tunnel --url http://localhost:3001   # терминал 2, выдаст https://xxx.trycloudflare.com
   ```
   Затем перезапустите сервер с публичным адресом, чтобы QR вёл на туннель:
   ```bash
   # bash / macOS
   PUBLIC_URL=https://xxx.trycloudflare.com npm start
   # PowerShell
   $env:PUBLIC_URL="https://xxx.trycloudflare.com"; npm start
   ```
   С ngrok то же самое: `ngrok http 3001` → `PUBLIC_URL=https://….ngrok-free.app`.

### Сценарий проверки (acceptance)

1. Откройте `/host` на ноутбуке или телевизоре → «Создать игру». Появятся QR-код, код комнаты и пустой список игроков.
2. Отсканируйте QR двумя телефонами. На каждом:
   - введите имя;
   - сделайте фото, украсьте его (фильтр, зеркало, стикеры);
   - выберите робота;
   - нажмите «Я ГОТОВ!».
3. На экране ведущего появятся роботы с фото на груди и статус Ready → «▶ Начать игру».
4. На телефонах выберите ответы. После ответа кнопки блокируются. Если не ответить за 15 секунд, засчитывается «⏱ Нет ответа».
5. Дальше игра идёт сама:
   - когда ответили все или вышел таймер, ведущий показывает правильный ответ;
   - роботы бегут на свои платформы;
   - через 1,5 секунды неправильные люки раскрываются и роботы падают;
   - правильные роботы прыгают под конфетти, очки обновляются.
6. Экран итогов. «⏭ Следующий вопрос» запускает следующий вопрос; без нажатия он начнётся сам через 8 секунд.
7. После 4-го вопроса — финал с рейтингом и карточкой «ПОБЕДИТЕЛЬ!».

Кнопки ведущего:
- **«↺ Перезапустить»** — те же игроки возвращаются в лобби, очки обнуляются.
- **«✚ Новая игра»** — закрывает комнату и создаёт новую.

Переподключение:
- Обновили страницу на телефоне или пропала связь — игрок вернётся под тем же `playerId` с сохранёнными очками (токен в `localStorage`). Отключившийся игрок не блокирует раунд.
- Ведущий после перезагрузки страницы возвращается в свою комнату по `hostToken`.

## Настройки

- `shared/src/config.ts`:
  - `ANSWER_TIME_SECONDS`, `CORRECT_POINTS`, `SPEED_BONUS_MAX`;
  - длительности фаз;
  - `NEXT_QUESTION_AUTO_SECONDS` (0 — переход только по кнопке);
  - `MAX_PLAYERS`, размер фото.
- `shared/src/theme.ts`: цвета платформ A/B/C/D и роботов.
- `shared/src/questions.ts`: вопросы (сейчас 4 тестовых на русском).
- `QUIZ_TIME_SCALE=0.5` (переменная окружения сервера) ускоряет все таймеры. Удобно для разработки.

Очки: правильный ответ даёт 100 плюс бонус за скорость до 50, линейно от оставшегося времени. Неправильный ответ и отсутствие ответа — 0.

## Проверки

```bash
npm run typecheck   # TypeScript во всех пакетах
npm test            # интеграционный тест сервера: полный цикл на реальных сокетах
npm run build
npm run e2e         # headless Chrome: ведущий + 2 телефона (фейковая камера) + 3 бота, 4 вопроса
```

`npm run e2e` ищет Chrome или Edge в стандартных путях; другой путь задаётся через `CHROME_PATH`. Скриншоты всех ключевых фаз сохраняются в `e2e/screenshots/`.

## Ограничения MVP

- Комнаты и фото хранятся в памяти сервера и пропадают при его перезапуске.
- Один набор из 4 вопросов, без редактора вопросов.
- 3D рассчитано на ноутбук ведущего. На слабом железе можно уменьшить тени в `ArenaScene.ts` (`shadow.mapSize`).
